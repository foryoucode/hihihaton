# Северный код

Vue-интерфейс, backend на Go и отдельный Python-сервис нейросети. Чтение CSV, поиск моделей, диагностика, точный расчёт, проверка рекомендаций и история — в Go. SQLite доступна только Go-приложению: запросы генерирует sqlc, миграции выполняет Goose.

## Запуск

Самый быстрый вариант — из корня репозитория (на уровень выше `north-code`):

```bash
docker compose up --build -d --wait
```

Нужны только Docker и Compose v2. Сайт доступен на `http://localhost:8080`. Go, Node.js и Python на компьютере устанавливать не требуется. История хранится в volume `station_data`, миграции применяются автоматически, модель уже обучена. Остановка: `docker compose down`. Просмотр журналов: `docker compose logs -f`.

Ниже — запуск без Docker для разработки.

Нужны Python 3.12+, Go 1.23.4+, GCC для SQLite-драйвера, Node.js 20.19+ и npm. Команды из `north-code`:

```bash
bash scripts/install.sh
bash scripts/start.sh
```

Сайт: `http://127.0.0.1:8080`. Остановка — Ctrl+C. Скрипт запускает Go backend и Python inference. Goose применяет миграции при запуске Go. Обученная модель включена в репозиторий. Журналы: `runtime/backend.log`, `runtime/neural.log`.

Можно работать без Python:

```bash
START_NEURAL=0 bash scripts/start.sh
```

Точный расчёт, поиск, диагностика и история продолжают работать. Нейросетевой запрос при недоступном сервисе возвращает понятную ошибку, без скрытой подмены метода.

Переменные: `APP_ADDRESS` — адрес Go-сервера, `NEURAL_PORT` — порт локальной нейросети, `NEURAL_URL` — её HTTP-адрес, `NORTH_DB_PATH` — файл SQLite. По умолчанию БД находится в `runtime/plans.db`. Приложение рассчитано на локальную работу без авторизации.

Для разработки интерфейса при запущенном backend:

```bash
cd client
npm run dev
```

## Структура

```text
backend/
  cmd/main.go                    запуск Go backend
  cmd/migrate/                   команды миграций Goose
  db/migrations/                 SQL-миграции
  db/queries/                    исходные запросы sqlc
  sqlc.yaml                      конфигурация генерации
  internal/handler/              Gin HTTP API
  internal/service/              сценарии, валидация, клиент нейросети
  internal/planner/              диагностика и точный алгоритм на Go
  internal/repository/           работа с историей
  internal/repository/sqlc/      сгенерированный Go-код
engine/
  server.py                      только /health и /recommend
  neural.py                      обученная MLP и поиск по её оценкам
  train.py                       офлайн-обучение и эксперименты
  planner.py                     офлайн-эталон MILP для обучения
  models/                        веса и отчёт экспериментов
client/                          Vue 3, Options API
```

Python-сервис не читает CSV, не открывает БД, не обслуживает CRUD и не запускает точный решатель. Go отправляет подготовленные признаки, Python возвращает варианты закупок, Go проверяет каждый вариант и заново считает стоимость, сроки и приоритеты.

## sqlc и Goose

SQL-запросы истории находятся в `backend/db/queries/plans.sql`. Код в `internal/repository/sqlc` создан настоящим sqlc v1.29.0 и включён в репозиторий. Для обычной сборки генератор не нужен.

После изменения SQL при установленном sqlc v1.29.0:

```bash
bash scripts/generate.sh
```

Сгенерированные файлы не редактируются вручную.

Первая миграция Goose создаёт таблицу `plans`. Она совместима с прежней Python-БД: существующая таблица и история сохраняются. Служебная таблица Goose отслеживает версии, повторный запуск не повторяет миграцию.

Ручные команды из `north-code`:

```bash
source scripts/env.sh
cd backend
go run ./cmd/migrate status
go run ./cmd/migrate up
```

Команда `go run ./cmd/migrate down` откатывает последнюю миграцию. Для первой миграции это удаление таблицы истории; используйте на тестовой базе либо после резервного копирования. Проверка down/up выполняется только на временной БД тестов.

## Функции

- Выбор точного и нейросетевого метода, сравнение на одном сценарии.
- Бюджет, срок и отключение поставщиков.
- Диагностика объектов и причины замены оборудования.
- Заказы по поставщикам, доставка, календарь готовности, стоимость восстановления разного количества пунктов.
- Независимый поиск моделей и просмотр предложений.
- Создание, чтение, переименование и удаление истории, экспорт JSON и CSV.

Исходные CSV находятся в `data`: UTF-8 с BOM, разделитель `;`. Нужен согласованный комплект. Загрузка CSV через браузер пока не реализована.

## Точный алгоритм Go

Перебираются наборы необязательных объектов и доступных поставщиков. Для фиксированного набора строится сеть: источник → потребности → предложения → сток. У потребности пропускная способность 1, у предложения — общий остаток, стоимость назначения — цена единицы. Минимальный стоимостной поток находит самую дешёвую закупку. Доставка добавляется один раз поставщику.

Перебор всех наборов поставщиков учитывает фиксированную стоимость доставки. Для ускорения используются нижние оценки стоимости: отсечение выполняется только когда набор не может улучшить уже найденный результат. Перебирая наборы пунктов, сохраняем минимальную стоимость для каждого количества восстановленных мобильных объектов.

Итог выбирается по кортежу:

```text
(превышение бюджета, -количество мобильных пунктов, стоимость)
```

Обязательные потребности — жёсткие ограничения. Мощности не складываются, температура и единицы проверяются, готовность устройства равна доставке плюс установке. Работы параллельны. При отмене или тайм-ауте результат не объявляется оптимальным. Демонстрационный предел — 10 необязательных объектов и 12 поставщиков; перебор экспоненциальный.

Исходная станция: **2 482 000 ₽**, оборудование — 2 212 000 ₽, доставка — 270 000 ₽. Восстановлены B01, B02, B03, M01, M02, M05 к 14-му дню. Остаток — 118 000 ₽.

## Нейросеть и эксперименты

MLP на NumPy: 10 входов → 24 tanh → одна оценка покупки. Обучение парному ранжированию ответов офлайн-MILP, Adam. Поиск с лучом ширины 8 собирает планы по оценкам сети. В рабочем приложении Go проверяет все закупки и выбирает лучший найденный допустимый вариант; точный решатель в этом режиме не вызывается.

Включённая модель восстанавливает три мобильных пункта за **2 537 000 ₽**, на 55 000 ₽ дороже оптимума. Оптимальность не гарантируется; отсутствие найденного сетью плана не доказывает невозможность восстановления.

Повторное обучение:

```bash
bash scripts/train.sh --scenarios 180 --test-scenarios 8
```

Учебные seed — 1000–1179; валидация — 100000–100019; тест — 200000–200007. Генерируются цены, остатки, доставка и повреждения. Веса и отчёт записываются в `engine/models`. Обучать параллельно с рабочими расчётами не следует.

Таблица экспериментов содержит результаты ранее выполненного офлайн-сравнения с MILP. Интерактивный точный метод теперь реализован на Go. Метрика парного ранжирования не означает долю оптимальных планов. Время зависит от машины, побитовая воспроизводимость между версиями BLAS/HiGHS не гарантируется.

Данные синтетические и основаны на одной учебной станции. Это демонстрация ML-пайплайна, а не подтверждение качества на реальных станциях. CVAE, WGAN-GP и LLM не используются. SciPy нужен для офлайн-обучения и эталонных тестов, а не для работы Go-backend или inference.

## Проверки

```bash
bash scripts/test.sh
```

Go: эталонный результат и граница стоимости, сравнение потокового алгоритма с полным перебором случайных маленьких задач, общие остатки, температурные ограничения, тайм-аут/отмена, отклонение поддельных рекомендаций, CRUD без Python, сохранение старой истории и повторные/обратные миграции Goose.

Python: inference, отсутствие вызовов MILP в нейросетевом режиме, отсутствие backend-маршрутов, воспроизводимость генератора и эталон для офлайн-обучения.

## API

| Метод | Маршрут Go | Назначение |
|---|---|---|
| GET | `/api/health` | База и доступность нейросети; отсутствие Python не делает Go неработоспособным |
| GET | `/api/data` | Каталог, станция и метаданные модели |
| POST | `/api/search` | Поиск: equipment_type, capacity, temperature |
| POST | `/api/calculate` | Расчёт: method (`exact` / `neural`), budget, deadline, disabled_suppliers |
| GET | `/api/experiments` | Отчёт офлайн-экспериментов |
| GET / POST | `/api/plans` | История / создание проверенного расчёта с name и параметрами |
| GET / PATCH / DELETE | `/api/plans/:id` | Чтение / переименование / удаление |

Python слушает только loopback: `GET /health`, `POST /recommend`. API БД у Python нет. При сохранении Go повторно выполняет расчёт и проверку, а не доверяет результату из браузера.
