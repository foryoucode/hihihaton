# Северный код

Планирование восстановления станции двумя способами: точная оптимизация и обученная нейросеть. Go API, Vue 3, Python с NumPy и SciPy. SQLite хранит историю сценариев в `runtime/plans.db`.

## Запуск

Нужны Python 3.12+, Go 1.23.4+ и Node.js 20.19+ с npm. Команды выполняются из `north-code`:

```bash
bash scripts/install.sh
bash scripts/start.sh
```

Сайт: `http://127.0.0.1:8080`. Остановка — Ctrl+C. Запускать нужно оба сервиса; скрипт делает это автоматически. Журналы находятся в `runtime`. Обученная демонстрационная модель уже включена в репозиторий.

Для разработки интерфейса после запуска сервисов:

```bash
cd client
npm run dev
```

Vite передаёт `/api` в Go backend. Для другого адреса сайта задайте `APP_ADDRESS`, для порта расчётного сервиса — `ENGINE_PORT`. Приложение предназначено для локальной работы без авторизации.

## Что доступно

- Выбор точного или нейросетевого метода и сравнение их результатов на одном сценарии.
- Изменение бюджета, срока и доступности поставщиков.
- Диагностика оборудования с причинами замены и состоянием каждого объекта.
- Закупки по поставщикам, общая доставка, календарь готовности, сравнение стоимости восстановления разного количества пунктов.
- Отдельный поиск моделей по характеристикам и просмотр предложений с причинами исключения.
- Создание, чтение, переименование и удаление сохранённых планов. Экспорт JSON и закупок в CSV.

Исходные CSV лежат в `data`. Чтение: UTF-8 с BOM, разделитель `;`. Заменять нужно согласованный комплект файлов. Загрузка произвольных CSV через браузер пока не реализована.

## Точный метод

Перебираются 32 сочетания пяти необязательных объектов. Для каждого HiGHS решает MILP: бинарное назначение предложения потребности, ограничения общего остатка и включение единой доставки поставщика. Мощности не складываются. Готовность устройства — доставка плюс установка, объекта — максимум готовности устройств.

Из допустимых планов выбирается минимум кортежа:

```text
(превышение бюджета, -количество мобильных пунктов, стоимость)
```

Все обязательные потребности включены как жёсткие ограничения. Оптимальность объявляется только после подтверждения решателем всех нужных подзадач. Лимит каждой подзадачи — 15 секунд; при неподтверждённом результате возвращается ошибка, а не обещание оптимума. Демонстрационный перебор ограничен десятью необязательными объектами.

На исходных данных: 2 482 000 ₽, из них оборудование — 2 212 000 ₽, доставка — 270 000 ₽. Восстанавливаются B01, B02, B03, M01, M02, M05. Готовность — 14 дней. Остаток — 118 000 ₽.

## Нейросеть

Настоящая MLP на NumPy: 10 входов, 24 скрытых нейрона с tanh, один выход — оценка покупки. Обучение парному ранжированию ответов MILP, оптимизатор Adam. Характеристики включают цену, добавочную стоимость с доставкой, уже оплаченную доставку, запас времени, характеристики модели, остаток и покрытие оставшихся потребностей поставщиком.

Для каждого набора пунктов сеть последовательно оценивает предложения. Поиск с лучом ширины 8 сохраняет наиболее вероятные последовательности закупок. Фильтруются неподходящие устройства и недоступные остатки. Итоговые планы проходят отдельную проверку. Выбирается лучший найденный план по тем же приоритетам ТЗ. Нейросетевой режим не вызывает MILP и не подменяется им при ошибке.

На исходных данных включённая модель находит допустимый план за 2 537 000 ₽ и восстанавливает три мобильных пункта. Это на 55 000 ₽ дороже точного результата. Оптимальность сети не гарантируется. Если она не нашла план, это не доказывает, что его нет.

## Обучение и эксперименты

```bash
bash scripts/train.sh --scenarios 180 --test-scenarios 8
```

Обучение пересоздаёт `engine/models/ranker.npz` и `metrics.json`. При работающем сайте обновите страницу после завершения обучения; обучать параллельно с расчётами не следует.

- Учебные сценарии: seed 1000–1179, 180 сценариев. Для каждого генерируются цены, остатки, условия доставки и повреждения; MILP даёт целевой план для выбранного набора объектов.
- Валидация: seed 100000–100019. Метрика парного ранжирования не равна доле оптимальных планов.
- Тест: seed 200000–200007. Точный и нейросетевой способы получают одинаковые сценарии. Отдельно показаны превышение, число пунктов и стоимость; полное совпадение с оптимумом отмечается только при равенстве всех трёх.
- Все генераторы используют фиксированные seed. Время работы зависит от машины. Побитовая идентичность результатов между версиями BLAS/HiGHS не гарантируется.

Это синтетический демонстрационный эксперимент на структуре одной станции. Он не доказывает качество на реальных данных и не проверяет перенос на другие топологии станций. CVAE, WGAN-GP и LLM не используются. Точная оптимизация остаётся эталоном для проверки качества.

## Проверки

```bash
bash scripts/test.sh
```

Проверяются эталонная стоимость и граница сценариев, порядок бюджетных приоритетов, температура, общие остатки, невозможные сроки, недопустимые планы, воспроизводимость генератора, отсутствие вызовов MILP в нейросетевом режиме, CRUD SQLite через HTTP и передача выбранного метода из Go.

## API

Go обслуживает сайт и `/api/*`, расчётный Python-сервис доступен только на loopback.

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/health` | Готовность сервиса и наличие модели |
| GET | `/api/data` | Каталог, станция и метаданные модели |
| POST | `/api/search` | Поиск моделей: equipment_type, capacity, temperature |
| POST | `/api/calculate` | Расчёт: method (`exact` / `neural`), budget, deadline, disabled_suppliers |
| GET | `/api/experiments` | Отчёт обучения и тестовых экспериментов |
| GET / POST | `/api/plans` | Список / создание расчёта с name и параметрами сценария |
| GET / PATCH / DELETE | `/api/plans/:id` | Чтение / изменение названия / удаление |

Создание сохранённого плана повторно выполняет расчёт на сервере: браузер не может сохранить поддельный результат как проверенный.
